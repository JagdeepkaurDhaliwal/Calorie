CURRENT PROJECT STATE & DEVOPS AUDIT
==================================================

CalorieCast is a full-stack, AI-powered health, fitness, nutrition, and calorie expenditure tracking system with:
1. Backend: FastAPI (Python 3.14) REST API & WebSocket server with SQLAlchemy ORM, SQLite database, Pydantic v2 schemas, JWT authentication, and Scikit-Learn ML models.
2. Machine Learning: 7-feature calorie regression models (Linear Regression, Random Forest, KNN, MLP/ANN) and 7-day Exponential Moving Average (alpha=0.5) weekly forecasting.
3. Mobile & Web Frontend: Pure vanilla JavaScript, modern CSS3 (responsive grid, mobile bottom nav bar, swipeable carousels), Service Worker (/sw.js), Web App Manifest (/manifest.json), and interactive SVG Anatomical Body Calorie Map highlighting active muscle groups in RED (#ef4444).
4. Native Android App: Self-contained, zero-latency Android application (android/) built with Gradle 8.5, Android SDK 34, AndroidX, Material Design 3, SwipeRefreshLayout, AndroidX WebViewAssetLoader, and multi-state native error recovery architecture.
5. Cloud & Vercel Deployment: Configured for modern serverless deployment with `api/index.py` entrypoint and `vercel.json` rewrite routing.
6. Size & Hygiene: Total project directory size is strictly 52.00 MB (well below the 2 GB threshold). Model weights compressed with joblib (80% reduction from 17.7 MB to 3.48 MB).
7. Test Suite: Automated pytest suite with 37 tests (100% passing across auth, admin, AI agents, exercises, forecast, ML registry, nutrition, predict, sessions, and workouts).

==================================================
1. ERROR RESOLUTION & BUG FIXES
==================================================

1. Missing Vercel Entrypoint & Routing:
   - Problem: The repository lacked a Vercel serverless function entrypoint and deployment configuration (`vercel.json`), causing deployment failures when imported into Vercel.
   - Fix: Created `api/index.py` exposing FastAPI's `app` with automated path resolution, and `vercel.json` routing all API and static requests seamlessly.

2. Heavy Unneeded Dependency in requirements.txt:
   - Problem: `tensorflow>=2.14.0` was listed in `requirements.txt`. TensorFlow unpacks to >500 MB - 1 GB, instantly exceeding Vercel's 250 MB serverless function bundle limit.
   - Fix: Removed `tensorflow` from `requirements.txt`. The active production ML models utilize Scikit-Learn and Joblib (`scikit-learn>=1.3.0`, `joblib>=1.3.0`), which are lightweight and execute with high efficiency.

3. Clean Database Cold-Start Issue (Ephemeral /tmp on Vercel):
   - Problem: In serverless environments like Vercel or on a fresh clone, SQLite database is created anew in `/tmp/caloriecast.db`. Without initial user seeds or model version records in the DB, `registry.has_active()` evaluated to False and logins failed.
   - Fix: Updated `app/main.py` lifespan to:
     * Auto-register baseline model version 1 (`ml/artifacts/v1`) into the database if empty.
     * Auto-seed demo user (`alex@example.com` / `Password123!`).
     * Auto-seed administrator accounts (`admin@caloriecast.local` / `AdminPassword123!` and `admin@example.com`).

4. Untracked Baseline Model in Git (.gitignore Fix):
   - Problem: `.gitignore` originally had `ml/artifacts/`, which prevented the trained production model weights from being tracked in Git. Deployments on GitHub / Vercel therefore had no model artifacts.
   - Fix: Modified `.gitignore` to track `ml/artifacts/v1/**` while ignoring temporary retraining job runs (`ml/artifacts/v*`).

5. Inconsistent Uploads Directory Path:
   - Problem: `app/routers/ai_agent.py` used a relative `"uploads"` directory instead of `ROOT_DIR / "uploads"`, creating split directories if executed from subfolders.
   - Fix: Unified `UPLOAD_DIR` in `ai_agent.py` to use `str(Path("/tmp/uploads") if os.environ.get("VERCEL") else (ROOT_DIR / "uploads"))`.

6. Incomplete Offline Mock Provider in api.js:
   - Problem: `api.js` lacked mock mappings for `/ai/assistant-chat`, `/ai/current-plan`, `/nutrition/today`, `/exercises`, and `/sessions`.
   - Fix: Expanded `getMockResponse` in `frontend/js/api.js` with complete, realistic fallback responses for every page.
